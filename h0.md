## a) Debian 13 paikalliseen virtuaalikoneeseen

**Ajankohta:** 27.10.2026

**Lopullinen ohjelmisto ja tehdyt valinnat**

- Virtualisointiohjelma: Oracle VirtualBox
- Käyttöjärjestelmä: Debian GNU/Linux 13 (Trixie)
- Virtuaalikoneen prosessorit: 2 vCPU
- RAM-muisti: 8 Gt
- Virtuaalilevy: 60 Gt, dynaamisesti varattu
- Hostname: `loc1`
- Domain name: jätettiin tyhjäksi
- Asennusmenetelmä: Graphical Install
- Levyn osiointi: Guided – use entire disk
- Ohjelmistolähteet: verkkopeilipalvelin käytössä
- Työpöytäympäristö: XFCE
- SSH server: valittu
- Standard system utilities: valittu
- Web server: ei valittu
- GRUB-käynnistyslatain: asennettu

**Ensimmäisen asennusyrityksen ongelma**

- Tein ensimmäisen asennuksen VirtualBoxin "Proceed with Unattended Installation" vaihtoehdolla.
- Asennuksen loppupuolella tuli virhe `Failed to run preseeded command`.
- Asennus kuitenkin jatkui loppuun asti, mutta päätin silti luoda virtuaalikoneen uudelleen. Tämä johtui siitä, että ensimmäisellä kerralla varasin virtuaalilevyn kooksi vahingossa vain 20Gt. 
- Uudessa asennuksessa ei käytetty "Proceed with Unattended Installation" vaihtoehtoa.

**Lopputulos**

- Debian 13 asentui onnistuneesti.
- XFCE-työpöytä käynnistyi ja virtuaalikone saatiin käyttöön.

## b) VPS-palvelimen hankinta

**Ajankohta:** 27.10.2026

**Palveluntarjoaja:** UpCloud

- Loin UpCloud-tilin ja vahvistin sen.
- Voimassa olleen tarjouksen vuoksi tilille aktivoitui 500 € arvoa 30 päiväksi.
- Loin Palvelimen Deploy Server -toiminnolla.
- Sijainniksi valittiin FI-HEL2, koska FI-HEL1 ei ollut kokeilutilillä käytettävissä.
- Palvelintyyppi: Starter
- Prosessori: 1 vCPU
- RAM: 1 Gt
- Tallennustila: 10 Gt
- Hinta: 3 €/kk (ensimmäistä kuukautta ei tarvinnut maksaa, koska se veloitettiin tarjouksena saadulta arvolta).
- Käyttöjärjestelmä: Debian 13 (Trixie)
- Server name: `vps1`
- Hostname hallintapaneelissa: `vps1`

Muut palvelinasetukset jätin oletusarvoihinsa tai tyhjiksi.

### SSH-avaimen luominen

Paikallisella VM Debianilla loin SSH-avainparin:

`ssh-keygen -t ed25519`

Julkinen avain sijaitsi tiedostossa:

`~/.ssh/id_ed25519.pub`

Avaimen kopioimisessa Windowsiin tuli ongelma, koska VirtualBoxin jaettu leikepöytä ei toiminut. Minulla oli UpCloud hallintapaneeli auki Windowsin puolella jonka vuoksi tarvitsin avaimen sinne. Olisin toki voinut kirjoittaa sen käsin, mutta halusin kopioida sen jottei avaimeen tulisi kirjoitusvirhettä.

Ratkaisuna käytin VirtualBoxin NAT-porttiohjausta johon syötin seuraavat tiedot:

- Host IP: 127.0.0.1
- Host Port: 2222
- Guest Port: 22

Nyt pystyin komennolla `ssh -p 2222 olli@127.0.0.1 "cat ~/.ssh/id_ed25519.pub" | Set-Clipboard` ottamaan VM puolelta avaimen Windowsiin ja sain sen
liitettyä UpCloudin hallintapaneeliin.

UpCloudissa SSH-avaimen nimeksi tuli `olli@loc1`.

### SSH-yhteys VPS-palvelimeen

Otin paikalliselta Debianilta yhteyden VPS-palvelimeen:

`ssh root@212.147.243.147`

Ensimmäisellä yhteydellä SSH pyysi vahvistamaan palvelimen ED25519-avaimen sormenjäljen.

Vertasin sormenjälkeä UpCloudin konsolissa näkyvään palvelinavaimeen. Sormenjäljet täsmäsivät, joten hyväksyin SSH-yhteyden.

Kirjautuminen VPS-palvelimelle onnistui.

### Hostnamen korjaaminen

UpCloudin hallintapaneelissa muutettu hostname ei ollut päivittynyt Debianin sisälle.

Tarkistin:

`hostnamectl`

Muutin nimen:

`hostnamectl set-hostname vps1`

Varmistin muutoksen:

`hostname`

Tuloksena oli `vps1`.

## c) Virtuaalipalvelimen alkutoimet

### Sudo-käyttäjän luominen

Loin uuden käyttäjän komennolla:

`adduser olli`

Tämän jälkeen lisäsin käyttäjän sudo-ryhmään:

`adduser olli sudo`

### SSH-kirjautuminen uudella käyttäjällä

Loin käyttäjälle olli SSH-hakemiston:

`install -d -m 700 -o olli -g olli /home/olli/.shh`

Kopioin Root-käyttäjän `authorized_keys`-tiedoston käyttäjälle olli:

`install -m 600 -o olli -g olli /root/.ssh/authorized_keys /home/olli/.shh/authorized_keys`

**Ongelma**

Kokeilin kirjautua käyttäjällä olli, mutta se epäonnistui virheilmoituksen vuoksi:

`Permission denied (publickey)`

Tämä johtui SSH-hakemiston nimestä joka oli kirjoitettu muodossa `/home/olli/.shh` vaikka se olisi kuulunut kirjoittaa `/home/olli/.ssh`.

Nimesin hakemiston uudelleen:

`mv /home/olli/.shh /home/olli/.ssh`

Kokeilin kirjautumista uudelleen ja se onnistui:

`ssh olli@212.147.243.147`

### UFW-palomuurin asennus

Päivitin pakettiluettelon ja asensin UFW:

`sudo apt update`

`sudo apt install ufw`

Avasin SSH-portin ennen palomuurin käyttöönottoa:

`sudo ufw allow 22/tcp`

Seuraavaksi aktivoin palomuurin:

`sudo ufw enable`

### Järjestelmän päivitykset

Päivitin pakettiluettelon ja asennetut ohjelmistot:

`sudo apt update && sudo apt upgrade`

Tämä onnistui ilman ongelmia.

### Root-käyttäjän salasanan lukitseminen

Tämä onnistui komennolla:

`sudo usermod --lock root`

## d) Web-palvelimen asentaminen

Asensin Apache2 komennolla:

`sudo apt install apache2`

Avasin HTTP-portin 80:

`sudo ufw allow 80/tcp`

Tarkistin toimiko palvelu:

`systemctl status apache2`

**Tulos:** `active (running)`

Tarkistin palomuurin asetukset:

`sudo ufw status`

**Tulos:**

- TCP 22 – ALLOW
- TCP 80 – ALLOW
- Vastaavat säännöt myös IPv6:lle.

### Verkkopalvelimen testaus

Avasin Windowsissa Firefox-selaimessa VPS-palvelimen osoitteen http://212.147.243.147/

Selaimessa näkyi:

**Apache2 Debian Default Page – It works!**

Verkkopalvelin oli siis saavutettavissa internetistä.
